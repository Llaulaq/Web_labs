## Что сделано

- Реализован CRUD API для сущности `User` на FastAPI (`app/users.py`):
  - `GET /users` — список с пагинацией (`skip`, `limit`) и поиском (`search`)
  - `GET /users/{id}` — получение одного пользователя
  - `POST /users` — создание (ответ **201**)
  - `PUT /users/{id}` — обновление (частичное: передаются только изменяемые поля)
  - `DELETE /users/{id}` — удаление (ответ **204** без тела)
- Бизнес-правило: уникальность email — дубликат даёт **409 Conflict**
- Ручная OpenAPI-спецификация: `openapi/users.yaml`
- Автоматическая документация: `http://localhost:8000/docs` (Swagger UI)

## Проверка работы (curl)

```
POST /users {"name":"John Doe","email":"john@example.com","age":30} → 201
POST /users (тот же email)                                        → 409
GET  /users                                                       → 200
GET  /users/1                                                     → 200
GET  /users/99                                                    → 404
PUT  /users/1 {"age":31}                                          → 200
DELETE /users/1                                                   → 204
```

## Задание 1: Проектирование API для блога

**Posts** — `GET /posts`, `GET /posts/{id}`, `POST /posts`, `PUT /posts/{id}`, `DELETE /posts/{id}`
**Comments** — вложенный ресурс поста: `GET /posts/{id}/comments`, `POST /posts/{id}/comments`, `DELETE /comments/{id}`
**Tags** — `GET /tags`, `POST /tags`, `DELETE /tags/{id}`; привязка к посту: `PUT /posts/{id}/tags/{tagId}`
**Categories** — `GET /categories`, `POST /categories`, `PUT /categories/{id}`, `DELETE /categories/{id}`; посты категории: `GET /categories/{id}/posts`

Параметры: path — `id` сущности; query — `page`, `limit`, `search`, `sort`, фильтры (`tag`, `category`, `author`). Ответы — JSON с кодами 200/201/204/400/404/409.

## Задание 2: Выбор HTTP-методов

| Операция | Метод | Обоснование |
|----------|-------|-------------|
| Создать новый пост | POST | Создание подчинённого ресурса в коллекции |
| Получить список всех постов | GET | Безопасное чтение коллекции |
| Получить один пост по ID | GET | Безопасное чтение ресурса |
| Обновить весь пост | PUT | Полная замена ресурса (идемпотентно) |
| Изменить заголовок поста | PATCH | Частичное изменение ресурса |
| Удалить пост | DELETE | Удаление ресурса |
| Добавить комментарий к посту | POST | Создание подресурса |
| Получить комментарии поста | GET | Чтение подколлекции |
| Лайкать пост | POST | Операция изменения состояния (`POST /posts/{id}/like`); не является чистым CRUD |
| Получить популярные посты | GET | Чтение коллекции с фильтром/сортировкой (`GET /posts?sort=popular`) |

## Задание 3: Выбор статус-кодов

| Ситуация | Статус-код | Обоснование |
|----------|------------|-------------|
| Успешное создание ресурса | 201 | Ресурс создан |
| Успешное получение ресурса | 200 | Успешный ответ с телом |
| Ресурс не найден | 404 | Несуществующий ресурс |
| Неверные данные в запросе | 400 | Ошибка синтаксиса/валидации запроса |
| Пользователь не авторизован | 401 | Нет/неверные учётные данные |
| Нет прав на операцию | 403 | Аутентифицирован, но доступ запрещён |
| Ресурс уже существует | 409 | Конфликт состояния |
| Успешное удаление | 204 | Успех без тела |
| Внутренняя ошибка сервера | 500 | Непредвиденная ошибка |
| Сервис временно недоступен | 503 | Сервер недоступен (перегрузка, обслуживание) |

## Задание 4: Endpoint списка товаров

- **URL:** `GET /products`
- **Query-параметры:** `category` (фильтр), `min_price`, `max_price` (числа), `sort` (`price_asc`, `price_desc`, `name`), `page`, `per_page`, `search` (по названию)
- **Ответ 200:**

```json
{
  "items": [{"id": 1, "name": "Клавиатура", "price": 2500, "category": "peripherals"}],
  "page": 1,
  "per_page": 20,
  "total": 57
}
```

- **Ошибки:** 400 — некорректные параметры (`min_price` > `max_price`), 500 — внутренняя ошибка.

## Задание 5: Структура JSON-ответа

```json
// 1. Список пользователей
{"items": [{"id": 1, "name": "John", "email": "john@example.com"}], "total": 1, "page": 1, "per_page": 20}

// 2. Создание пользователя (201)

// 3. Ошибка валидации (400)
{"error": "validation_error", "message": "Некорректные данные", "fields": {"email": "Невалидный адрес"}}

// 4. Пагинация
{"items": [], "page": 2, "per_page": 20, "total": 57, "pages": 3}
```

## Задание 6: Идемпотентность

| Операция | Идемпотентная | Обоснование |
|----------|---------------|-------------|
| GET /users/123 | Да | Чтение не меняет состояние |
| POST /users | Нет | Каждый вызов создаёт новый ресурс |
| PUT /users/123 | Да | Повтор приводит к тому же результату |
| PATCH /users/123/email | Да | Установка конкретного значения |
| DELETE /users/123 | Да | Повторный вызов — тот же результат (ресурс отсутствует) |
| GET /users?page=1 | Да | Чтение с параметрами не меняет состояние |

## Задание 7: Практическая работа с httpbin

Выполнены запросы GET/POST/PUT/PATCH/DELETE к httpbin.org. Каждый эхо-эндпоинт возвращает **200** и JSON с отражёнными данными запроса: `url`, `headers`, `args` (query), `form`/`json` (тело), `method` — httpbin показывает, что тело и заголовки дошли корректно. Отличия тел: у GET пустое `args` заполняется query-строкой, у POST/PUT/PATCH — поле `json` с переданным объектом, у DELETE тело обычно пустое.

## Задание 9: Анализ JSONPlaceholder

```bash
curl https://jsonplaceholder.typicode.com/posts       # GET — 200, массив из 100 постов
curl https://jsonplaceholder.typicode.com/posts/1     # GET — 200, один объект {userId, id, title, body}
curl -X POST ... -d '{"title":"t","body":"b","userId":1}'  # 201, созданный объект с id: 101
curl -X PUT .../posts/1 -d '{...}'                    # 200, обновлённый объект
curl -X DELETE .../posts/1                            # 200, пустой объект {}
```

Структура ответов — плоские JSON-объекты без обёрток; коды соответствуют REST-соглашениям (201 на создание, 200 на чтение/обновление/удаление).
